# Orb architecture

`io.github.tcballard.orb` declares `menu` and `bar-widget`, mapping to the hosted `Item` in `Wheel.qml` and the optional `TouchWidget.qml` bar entry. The menu loader retains ownership of the shell facade. It exposes `open(payloadJson)`, `close()` and `opened`. `keepLoaded` avoids repeated construction and permits a 120ms launch handoff after unmapping. One keep-loaded menu owns the edge handle and bounded touch processes. There is no standalone Quickshell or external daemon, Rust helper, Python, network or privileged operation.

The local `OrbOverlay.qml`, built on Quickshell's `PanelWindow`, owns the focused-monitor surface and scale readiness. It retains the screen for each opening and waits for fullscreen geometry and matching output scale before revealing content. This avoids importing `qs.Ui.OverlayWindow`, which is absent in Omarchy 4.0.6. The desktop wheel uses exclusive keyboard focus while open. Settings and the touch home use on-demand focus and respect reserved space so a hosted keyboard can retain its target. Cancellation clears pointer sampling and pending launches, unmaps the layer and lets Hyprland restore focus. Completed actions hide before launching. Repeated summon resets one surface; toggle cancels it.

`hyprctl -j cursorpos` runs once per summon; failure falls back to monitor centre. `Model.js` clamps logical coordinates against reserved edges and tests radial hit regions. Selection starts neutral; sectors run clockwise from Browser at the top. `PointerMoveGate` prevents stationary pointer events replacing keyboard selection. Theme, typography, spacing and reduced-motion tokens are live bindings. Canvas redraws on palette/selection changes; `LineIcon.qml` draws original vector paths. `ActionIcon.qml` renders bundled Codex/Claude/Grok SVG marks, choosing contrasting variants from the menu background luminance; the generic icon is a fallback for unsupported agents or a failed asset load.

`~/.config/omarchy/orb.json` owns durable configuration, watched by FileView. Five to eight bounded top-level actions are validated, with one optional submenu level or the dynamic installed-agent catalog. All displayed labels are plain text. IPC payloads cannot provide commands or file paths. Configuration is trusted local code: `scripts/launch` executes argv without eval and notifies on missing/failed commands. Apps run independently of the shell's lifetime.

Normal `omarchy plugin add ... --enable` loads the keep-loaded menu. `scripts/setup` creates missing settings with a no-clobber hard link, then registers session-only Hyprland Lua binds. `BindingLifecycle.js` emits owner-scoped teardown code passed directly to `hyprctl eval` on unload, independent of the deleted checkout. Tombstones reject a late apply after teardown; generation ordering rejects stale instances. Unchanged keyboard, desktop and mouse-button handles are retained when adopting a new owner or changing activation settings. Only changed bindings are created and superseded handles removed: current Hyprland removes all bindings for the same key when removing a handle. This prevents a repeated setup from deleting its own replacement. Config changes and Hyprland reload reapply bindings. No standalone service or persistent binding config is needed. Errors surface in Orb settings with Retry. A hard shell crash can leave runtime handles until the shell restarts or Hyprland reloads.

The old installer’s exact unmodified module/include migrates with backups and reload/error rollback. Modified modules remain untouched. Local-source Git origins are changed only when that source’s own origin is this exact public repository, allowing later normal plugin updates. Config and unrelated desktop settings are preserved. Contracts checked against Omarchy `81fd2d23ca6e3462183a4dc8360de3113fa8d80c` and Hyprland `12f242511a9c0fe8a884a9d90511bbbbe044f067`.

The repository starts from the user's starter `0605227`; `.template/blueprint` is unchanged. Conventions were checked against installed Omarchy `5f7aaeb8c`, its active `dock-controls-desktop` checkout, and the upstream shell reference. Existing unrelated source edits were preserved.

Deferred: deeper nesting and physical multi-monitor acceptance.

The opt-in extra-button gesture owns a press/release pair through the same Hyprland Lua binding registry as the shortcut. Primary, secondary and middle mouse buttons are excluded; button codes 275–511 are explicit local settings. Conflicts across modifiers fail before registration. The two handles are retained and removed as one unit because Hyprland's `remove()` clears bindings for a key. Failed release registration removes the staged press and leaves the previous key intact. An old development-only mouse binding on the same key requires a shell restart for migration.

Hyprland emits owner-scoped custom socket events carrying pointer coordinates on press, movement and release. A single compositor timer samples only while held and stops on release, removal, owner change or a six-second timeout. This avoids relying on the overlay receiving a Wayland mouse release from another surface. The menu validates each event, retains the press position for placement and uses the captured release position for the same radial hit test as clicking. A quick stationary tap opens the wheel; a longer stationary hold, centre or outside release cancels. A released submenu remains open. The menu's watchdog clears an incomplete interaction. Live acceptance is still required: the Lua API contract was checked against Hyprland `efb50993780079460b0cbed1363e2166a2de1d9f`; portable fixtures do not establish real compositor or pointer behaviour.

The compact wheel defaults to 240 theme units. Submenus reuse the same circular geometry, position and diameter; their centre button returns to the main wheel. More than six submenu actions are paged using footer arrows, scrolling or Page Up/Down. Escape/Left/Backspace returns to the wheel; outside click closes the entire interaction. `scripts/agents` performs one read-only mise inventory query plus executable checks, excluding auto-install stubs. `scripts/agent` launches an installed client in Omarchy’s agent terminal with the selected account, without changing the default agent or submitting a prompt.

The built-in Files menu uses `"menu": "files"` and the same submenu/paging behaviour. `Model.fileActions` supplies nine fixed locations with distinct vector icons. `scripts/files` resolves Home and XDG user directories at activation time, then launches Nautilus with one literal path or Recent/Starred/Trash URI, using Omarchy’s setsid/uwsm-app handoff. Unknown locations and unavailable directories fail without launching. Validation normalizes only the original top-level Files command into this menu, without rewriting its saved document; app entries, custom paths, renamed commands and leaf commands inside user submenus remain unchanged.

The main hub uses a theme-accent glow on hover or Home-key selection. Activation opens a compact SettingsPanel inside the same overlay, centred in the focused screen’s usable area with a margin beyond reserved bar space. Its placement is independent of the pointer and wheel position. Slot choices, size and animation stay in a draft until Save. The latest configuration is re-read; only edited fields and slots are merged, preserving custom metadata and concurrent edits to untouched slots. Conflicting edits to the same slot are rejected. FileView writes atomically with success/failure handling. Cancel discards the draft. Submenu hubs still navigate back.

The menu-scoped `shell.appLibrary` supplies installed entries, labels and icon sources. Picker choices persist desktop IDs rather than guessed Exec strings, and `appLibrary.launch` runs after the same 120ms unmap handoff. Postcard uses its installed manifest ID `tahayvr.postcard` with an empty summon payload to open the editor. All slots share the same picker, while menu shortcuts retain their submenus. Search has a separate focus target; leaving it restores keyboard navigation to the slot panel.

`AppLibraryCompat.qml` delegates to that service when present. Omarchy 4.0.6's panel model can pass QVariantList kinds to a host check that requires a JavaScript array, omitting the service for menus. In that case Orb uses Quickshell's desktop-entry index, the shell's configured/desktop hide lists and icon lookup, and launches through the same literal `setsid uwsm-app -- gtk-launch <id>.desktop` path after dismissal. Application-list changes update an open picker without discarding its search or the settings draft. Animation durations use the newer `Style.duration` when available and the configured duration otherwise.

Optional `desktopRightClick` registers the callback from `desktop-click.lua` for the enabled menu’s lifetime. The unmodified right-button binding checks the pointer against windows on the active workspace and non-background layers. It uses the documented `auto_consuming` callback result so clicks over applications pass through. Background renderers (including Wallpaper Engine) count as desktop. Special workspaces and unknown geometry fail closed. There is no input daemon or additional surface for right-click handling. Existing unmodified right-click bindings block installation rather than being overwritten.

Six slots remain the default. The settings panel can append a seventh/eighth slot through the existing picker and remove entries down to five; choices remain drafts until Save. The slot list scrolls to keep the panel compact. Radial placement and hit-testing use the current count, with narrower labels above six. Structural saves reject concurrent slot edits and retain metadata on unchanged actions. Submenus still page in groups of six. Selected captions use the shell menu text colour; selected drawn shortcut icons remain white. Installed app icons retain native colours, and wheel selection surfaces use the shell menu palette.

The optional Make something cool catalog entry contains the same three starter prompts as Omarchy’s Agents panel. It uses normal one-level children and the supported `omarchy agent prompt` CLI, so the default agent/account and existing terminal launch behavior stay with Omarchy. No separate agent service or hard-coded provider is added.

Sectors contain centred icons at every wheel diameter; there are no in-sector labels or size breakpoint. The footer displays the full selected action label for both pointer and keyboard selection, including submenus. Its text, padding and pagination controls scale proportionally above the default 280px rendered diameter, retaining a readable minimum at smaller sizes. Placement reserves the scaled footer height when keeping Orb inside the monitor.

The settings editor uses the same hosted overlay. `WheelPreview.qml` supports pointer drag/release and click editing; `SettingsPanel.qml` also offers keyboard and button reordering. Draft origin arrays track each top-level action and submenu child, so moving/editing canonical fields retains unknown metadata. A three-way merge rejects external edits to changed slots, structural changes and opening/appearance fields while preserving untouched updates. `ActionEditor.qml` edits commands as separate argv fields and lazily loads a child editor for submenu leaves; no new shell-string execution is introduced. All changes remain drafts until Save. An unchanged save finishes explicitly because FileView does not emit `saved` for identical text; a watchdog recovers failed saves.

`ShortcutHistory.js` stores up to forty independent snapshots of shortcut actions, origin arrays and selection. Undo or Ctrl+Z restores the last shortcut edit, retaining appearance and activation drafts. Editor text fields keep their native Undo, and history clears when Settings begins a new draft. The Settings header reads the installed manifest version.

Opening settings are normalized/validated by `Model.js` using the same key grammar as `scripts/setup`. Before writing activation changes, the menu reads live `hyprctl binds -j` and rejects conflicting keyboard, desktop or mouse-button bindings. The setup helper repeats that check before registration. Settings use native tab-focusable buttons and fields; the scrollable body keeps focused controls visible and leaves Save/Cancel reachable. The status IPC remains read-only and includes editor control bounds for real-input acceptance tests.

Settings captures its opening height after the initial Shortcuts layout settles. Tabs, action editors, added rows and error messages keep that frame, with overflow scrolling inside it. The available monitor height still caps the panel when the display changes.

`ActionPicker.qml` supplies the shared searchable catalog for the action editor and the browser beside the wheel. Browser drags remain inside the hosted overlay: pointer coordinates map to `WheelPreview.qml` and use its existing radial hit regions. The target sector highlights before release; dropping in the centre or outside cancels. A successful assignment updates the draft and its child origins while retaining the slot's original metadata identity. Click and keyboard assignment use the same path. The compact layout keeps the picker and wheel beside each other when space permits, with separate scrolling inside the catalog.

Small, Medium and Large select diameters of 240, 360 and 480 theme units. They stage the existing `diameter` setting, so custom values and the fine-adjustment slider use the same validation, concurrent-edit protection and save/cancel flow. No additional configuration keys are introduced.

`WheelSurface.qml` draws the shared circle/polygon outline and sectors for the live wheel and draft preview. Polygon vertices align with the visible actions; `Model.edgeRadius` supplies the same boundary for drawing and pointer/drag hit-testing. The hub is always circular. Submenu pages use their own visible count; pages with one or two entries retain a circular outline. Five to eight top-level actions are supported, with six as the default. The optional `shape` setting defaults to `circle` for existing configurations and follows the same draft/save/cancel and concurrent-merge flow as other appearance settings.


## Touch ownership and lifecycle

`TouchModel.js` supplies mode selection, deterministic display choice, radial geometry and press/move/release state. Explicit output wins; otherwise a unique internal display or the only connected output is selected. Ambiguous outputs require a choice. Touch openings never sample the mouse position. A display disappearing closes the interaction. Layout changes cancel a pending selection; hold-to-edit cannot also launch. A scrollable grid retains target size when a fan or ring cannot fit.

`TouchHandle.qml` maps only while the configured touch mode is active and Orb is closed. It takes no keyboard focus and reserves no band. Its vertical position uses the existing three-way settings merge. `TouchWidget.qml` is an optional bar entry that opens the same menu on the bar’s output. `TouchHome.qml` reuses favourites, submenus, app-library launching and the draft editor. Window closes require a second tap. Window targets are revalidated immediately before dispatch; minimised windows restore to the selected display’s current workspace before focus and stacking.

`TouchBackend.qml` is the single process owner inside the keep-loaded menu. The view’s generation rejects late completions; cancellation stops its action and window query. Helpers bound stdout, runtime and errors. Automatic mode polls at five seconds and watches the provider’s fold-state file as a refresh hint, never as authorization. Window snapshots refresh at three seconds only while a touch view or settings is open. Actions are serialized, timeouts remain failures and a requested keyboard can queue behind an in-flight action.

`scripts/touch` accepts a closed set of typed operations. It validates window addresses, workspace IDs, connected monitor names and selected providers before constructing literal dispatcher arguments. Cross-plugin operations use `omarchy-shell shell listPlugins` and canonical CLI calls, never foreign shell service objects. Exit-zero `unknown`/dispatcher errors are failures. Tablet Mode owns folding, rotation and hardware input changes. OmaTouch or Tablet Mode owns the keyboard. Missing or disabled providers yield actionable errors, not automatic installation.

Touch text fields use `EditorField.qml`; editor and touch controls have at least 48px height. `ActionEditor.qml` opens a local image chooser while retaining the validated absolute-path input. The touch home reserves typing space because OmaTouch’s floating keyboard does not advertise an exclusive zone. After an Orb surface is remapped, an already requested keyboard is hidden and summoned again above it. This is provider-specific desktop layering, not a lock-screen implementation.

Legacy configurations default to Desktop. Touch and Automatic are explicit saved choices. Automatic requires enabled Tablet Mode plus a real fold sensor and a boolean folded observation; missing/unknown state does not change input devices or activate touch mode. The inspected contracts and physical acceptance requirements are recorded in [TOUCH.md](docs/TOUCH.md). No architectural change here establishes iPad kernel, graphics, touch-driver or secure-unlock support.
